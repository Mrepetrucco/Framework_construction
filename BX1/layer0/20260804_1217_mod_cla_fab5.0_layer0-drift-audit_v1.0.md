# Audit

## 1. Re-pointing does not retroactively undo chain topology — but the architecture is sound going forward, with one missing operation

Re-pointing changes the **validation edge**, not the **generative provenance**. AX7's content — its axis boundaries, its partitioning of obligations, its vocabulary — was selected inside 7POF's hypothesis space. That selection is baked into the content. The critical asymmetry:

- **Commissions** (things AX7 asserts that L0 doesn't support) — re-pointing catches these. A consistency check against L0 fails on false content.
- **Omissions** (things 7POF dropped that AX7 therefore never saw) — re-pointing is blind to these. A chain-derived artifact is typically *consistent* with every L0 id it cites while still carrying inherited gaps. Consistency-with-source ≠ derivability-from-source.

So the star claim is honest for future drift but launders past derivation. The fix is cheap and specific: one **coverage pass in the reverse direction** — enumerate L0 ids and ask which project into each artifact; any L0 id projecting into nothing is the inherited-omission residue. Note the document runs its example (D7) forward only.

BX1 is the exception: L0-D17 explicitly licenses derivation from the pair, so its chain history is owner-sanctioned — provided its *justifications* re-point, which the document does correctly.

## 2. Lazy remediation compounds; the cheap fix is inverting the default

Two defects in "re-point as next touched":

1. **The read precedes the repair.** The touch that triggers remediation is a consultation — the corrupted content has already acted before it's checked.
2. **Cross-contamination during repair.** Re-pointing entry A may consult entry B (still contaminated) to interpret the L0 id — paraphrase interpreting paraphrase, laundered into a "remediated" node.
3. Touch frequency correlates with use: cold entries stay contaminated indefinitely while retaining owner-tier authority.

**Cheapest sound alternative:** an immediate O(n) metadata sweep setting every unrepointed entry to `UNVERIFIED`. No re-derivation, no L0 lookup — one bit per entry. Any read of an `UNVERIFIED` entry is treated at Claude's-claim tier, not owner tier. Then lazy re-pointing proceeds as upgrade, not repair. This flips the default from *trusted-until-fixed* to *suspect-until-verified*, which kills compounding: a corrupted node can no longer transmit owner-authority through use. Cost is one sweep plus a tier check at read time.

## 3. Most dangerous delta: D2

D2 performs a **category promotion**: the owner stated "controlled not true" as a *property of governance* (plausibly a limitation acknowledgment — a caution about what governance can achieve); Claude converted it into a *universal design law* on every class. If the owner meant it descriptively or as a warning, the delta doesn't just extend the ruling — it may **invert its intent**, enshrining a deficiency as a mandate.

Compounding factors: enforcement is "all machinery," so the delta is diffused with no single audit point — once baked in, it is everywhere and locatable nowhere. Every other delta has a bounded enforcement site (X1, X2R, session-open) where it can be inspected and reverted.

Runner-up: D15, because the star-grounding rule *is itself a delta* (owner asked "how far," proposed no topology) — the correction framework validates against nothing but itself. Mitigated only by being transparently declared.

## 4. The unprojectable class: rulings whose verifier is the owner's judgment of meaning

Any ruling whose satisfaction condition is **interpretive** — high-fidelity, suitably-granular, intent-matching — cannot go into BX1, structurally not just practically. To mechanize it, the runner needs a formalization; the formalization is itself a Layer-1 delta; executing it converts an owner-adjudicated obligation into Claude's proxy **and stamps it "guaranteed"** — the worst possible mislabel, because BX1 is defined as the only projection that carries guarantees. Goodhart with an attestation attached.

Sub-class that is doubly impossible: self-referential rulings about the L0-relation itself (D15-class). BX1 is a projection of L0; it cannot mechanically verify its own fidelity to L0 without assuming the fidelity under test.

## 5. Undefended failure: silent L0 non-coverage

Every mechanism here validates **existing entries downward** (delta → L0 id, entry → re-point-or-ORPHAN). Nothing runs **L0 → projections**. An owner utterance that projects into nothing — dropped in the original 7POF derivation, never paraphrased into memory — passes every check in this architecture, forever, because star topology only audits edges that exist. Missing edges are invisible, and under lazy remediation nothing ever touches them. The ORPHANED marker catches deltas without owners; there is no inverse marker for **owners without deltas**. That is also exactly where Q1's unfixable chain residue lives.
