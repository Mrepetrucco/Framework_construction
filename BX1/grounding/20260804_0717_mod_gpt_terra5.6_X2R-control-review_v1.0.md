1) **No.** Determinism removes learned *runtime weights*; it does not remove priors.

Feature choice encodes priors about:

- which grammatical distinctions matter;
- what counts as a required role, resolvable deixis, imperative, quote span, or “domain term”;
- parser/tokenizer behavior and grammar coverage;
- feature thresholds, missing-value handling, and context boundaries;
- the policy designer’s mapping from predicates to exemplars.

If any extractor is statistical—POS tagging, coreference, quotation detection, semantic-role labeling—the learned component remains, merely upstream. Even a hand-built extractor is a fixed hypothesis class with human priors. The appropriate claim is **deterministic and auditable**, not prior-free.

2) **C2 creates an ambiguity-to-baseline incentive.**

Because the stub is empirically stronger than the richer examples in T5, an attacker or ordinary user may benefit from inducing underspecification, unresolved reference, or parser ambiguity. “Fail safe” can become “route to the observed best treatment.” That is both an evasion channel and a distribution-shaping mechanism.

It also invalidates the stated interpretation of C6:

- Routed calls are selected for high-confidence feature patterns.
- NULL calls become enriched for ambiguous, adversarial, malformed, or out-of-distribution prompts.
- Comparing routed outcomes with NULL-shadow outputs is then not a marginal treatment estimate; it is a comparison of different populations.
- A shadow output that is not executed does not reveal the counterfactual downstream outcome, especially where tools, user follow-up, or stochastic decoding matter.

C6 measures a useful diagnostic difference in generated text, not causal marginal contribution. Causal estimation requires randomized assignment within predeclared eligibility strata, paired decoding controls, and an outcome evaluator independent of the route policy.

Also: under X2R-2, a true multi-match should be impossible. A runtime multi-match is therefore an integrity fault—feature-extractor divergence, partial deployment, or policy-version mismatch—not ordinary ambiguity. It should quarantine/fail closed, not silently route to NULL.

3) **“>2 sigma” is not an admission criterion until the experiment is specified.**

Held-out prompts must be drawn from a versioned, provenance-tracked target distribution including:

- production prompts, stratified by route-relevant features;
- temporally later prompts, not merely random splits from the same corpus;
- adversarial and boundary prompts generated independently of rule authors;
- organization/domain/user segments likely to differ in grammar, terminology, and context quality;
- prompts with known downstream outcome labels, not just route labels.

The holdout must be inaccessible to rule authors until a frozen candidate rule is evaluated. Otherwise rule iteration leaks the test set.

For multiplicity: if \(m\) candidate rules, thresholds, feature combinations, or exemplar mappings were explored, a raw 2-sigma result is weak evidence. Require at least:

- preregistered candidate families and primary metric;
- family-wise control such as Holm–Bonferroni for hard admission, or FDR control for exploratory screening;
- sequential-testing correction if candidates are evaluated iteratively;
- confidence intervals on practical effect size, not only significance;
- an independent final confirmation set after policy freezing.

Two sigma is approximately a 5% uncorrected test. It is unsuitable as a general release gate when many rules were considered.

5) **Delete C6.**

As specified, it overclaims: logging what NULL *would have generated* is not continuous measurement of marginal contribution. It is a shadow-text comparison with severe selection bias and no observed counterfactual outcome. Retain it only if redesigned as a randomized controlled evaluation program; otherwise remove the causal language and treat it as telemetry.

**Missing control more important than all seven: an execution-time reference monitor.**

The router governs exemplar selection, not what the model ultimately does. Add an independent, fail-closed enforcement point between model output and any consequential action:

- canonicalize and validate model/tool outputs;
- authorize actions through typed, least-privilege capabilities;
- bind authority to authenticated user, task, context provenance, and policy version;
- enforce schemas plus domain invariants where possible;
- reject undeclared tools, arguments, destinations, and data flows;
- require explicit confirmation or independent verification for irreversible/high-impact actions;
- emit signed action-level audit records.

Without that control, a perfectly deterministic router can still feed a model that emits an unauthorized, malformed, exfiltrating, or unsafe tool call. The router is defense-in-depth; the reference monitor is the actual safety boundary.
