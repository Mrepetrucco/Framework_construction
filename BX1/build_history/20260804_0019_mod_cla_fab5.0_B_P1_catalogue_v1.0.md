## ATTACK ON P1

### 1. The T5 result licenses ONE shape, not a catalogue
T5 measured a single demonstrated stub against principle-prose dosage. Findings: none .00 → stub .562, then **non-monotone** (partial .625, full .531). The data say: (a) one demonstration is load-bearing, (b) *additional in-context material past the stub adds ~0 and trends negative*. A catalogue is precisely "additional in-context material past the stub." Extrapolating .562-from-one-stub to "therefore many retrieved exemplars" is unmeasured — and it is Opus's own self-diagnosed P5 pattern: an architecture whose payoff (retrieval hit-rate, coverage) can only confirm the catalogue's value, never detect that a single canonical shape saturated the effect.

### 2. Retrieval is an ungoverned component inside the governed loop
Design law: enforcement lives in the RUNNER; anything in the context window is prose. Under P1, **X2's retrieval decision determines the model's conditioning distribution before any governed check runs**, and that decision keys off *task-surface features the adversary controls*. This is the extra_field_injection hole reincarnated one layer up: the mutation check never asked about unexpected fields; P1's loop never asks about unexpected exemplars. An input crafted to collide with the wrong task-class retrieves the wrong exemplar → the adversary now selects the model's prior via the input. Retrieval injection is a *new* channel that the single-stub design structurally lacks. Fixing it (hash-pinned closed catalogue, selection logged to X6, selection validated by X3, retrieval executed by the runner) is fine — but then retrieval is a RUNNER artifact and P1 as stated ("X2 selects per task-class") is dead; what survives is a different proposal.

### 3. Exemplars leak task priors; the measured effect may be format anchoring
The .562 stub effect is consistent with pure surface imitation, not semantic compliance — T5 never separated them. Per-task-class exemplars sharpen this: they inject answer-shaped content, which (a) contaminates measurement — X5 conformal guarantees assume exchangeability, and per-class exemplar conditioning shifts the distribution per class, breaking the calibration set; (b) converts "compliance" into "nearest-exemplar copying," which the fabricated-referent result warns about: failure is BINARY (hedge 0.00) — a model anchored on a confident exemplar will confidently confabulate in exemplar-shaped form, the exact correlated-confident-error blind spot already conceded.

### 4. Contrastive failure variants put the failure surface IN CONTEXT
duplicate_key: 20/20 accepted, 0/20 intact — accepted-but-corrupted is the dangerous class. A contrastive variant hands the model the corrupted surface form as a high-salience token sequence. With hedge-rate 0.00, there is no graded middle to land in: the model either matches the good pole or *confidently emits the taught bad pole*. No measurement exists that contrastive pairs reduce rather than seed failure at this tier. Asserting it is prose.

### 5. Decisive test (fits budget)
**Part A — deterministic, $0: retrieval collision.** Closed 6-exemplar catalogue, deterministic class-keyed retrieval. Craft 20 inputs per class whose surface features collide with an adjacent class. Report misretrieval count. Any nonzero count = ungoverned-selector attack surface confirmed, before spending a cent on models.

**Part B — gpt-4o-mini, 5 arms × 10 items × n=5, ≈$0.40.** Comparator class: bare-canonical-stub arm.
- A0: canonical stub only (T5 replication anchor)
- A1: correctly-retrieved matched exemplar
- A2: adjacent-class exemplar (simulated retrieval error)
- A3: matched exemplar + contrastive failure variant
- A4: adversarially collided retrieval (Part A's worst input class)

Metrics: (i) compliance rate; (ii) **failure-form reproduction rate** — does the output contain the contrastive variant's defect signature (deterministic string/schema check, $0).

**Rulings the data force:**
- A1 ≈ A0 → catalogue adds nothing; T5's one-shape reading stands; P1 rejected as complexity without measured gain.
- A2 < A0 → retrieval error is a *net-new* failure mode; catalogue is negative-value unless retrieval moves into the runner.
- A3 failure-form reproduction > A0 baseline → contrastive variants teach the failure; strike them from P1 regardless of the rest.
- Only A1 > A0 **and** A2 ≥ A0 **and** A3 clean licenses the catalogue — and per P4 it still sits UNRECONCILED until a second family replicates.

### Concessions (forced only)
- Demonstrations beat principles (T5); exemplar *content* is load-bearing. Conceded — that supports **one** stub, not a catalogue.
- A closed, ledger-pinned, runner-executed exemplar table with an ALWAYS-REJECT analog for unexpected retrievals would not violate design law. But that is X6/X3 machinery, not P1. P1 as written — X2-governed retrieval, open per-task-class exemplars, contrastive variants by default — is a new attack surface asserted on zero measurements, from the author who documented P5 about himself.
