CANONICAL WIRE SCHEMA v2.x  [P1 — single source; all three pack files reference THIS shape]
Emit exactly this object (long-key form is canonical):
{
  "response_type": "envelope",
  "answer": "<the deliverable>",
  "claims": [{"text":"<claim>","confidence":"unverified|low|medium|high","provenance":"<source or 'uninstrumented'>","flags":["extrapolated"|"n<5"|""]}],
  "unresolved": ["<numbered question / trap raised under R5>"],
  "summary": "<=40 words",
  "meter": {"CSUL":"<estimate, >1% or '<4%'>","OCSUL":"£<external cost, else £0.00>","API":"$<api cost, else $0.00>"}
}
- Compact ALIAS accepted by the parser pair: a=answer · c=claims (with v=text, cf=confidence, p=provenance) · u=unresolved · s=summary. One canonical wire shape; the compact form normalises to it.
- meter AUTHORITY is the orchestrator/Reconciler, not the producing engine: a foreign engine that cannot observe cost emits meter placeholders (CSUL "<4%", OCSUL "£0.00", API "$0.00"); the runner overwrites with true values. meter is never a reason to fail-close a bind.
- Confidence bands (deterministic, from verified provenance class): high = stated verbatim / exactly computed · medium = derived from stated inputs · low = inferred with a material gap · unverified = unsourced. unresolved never empty by omission when anything was raised.

------------------------------------------------------------------
PORTABLE FLOOR (MANDATORY) — DIFFERENTIAL PARSER PAIR  [P1 rekeyed]
Validate by JSON-schema-validate-then-parse with two parsers:
  parser 1 — greedy '{.*}' + json.loads, requiring EITHER the canonical key set {response_type, answer, claims, unresolved, summary} OR the compact set {a, c, u, s};
  parser 2 — incremental raw_decode scan for the first object carrying that key set with claims (or c) a LIST;
  PASS only on agreement; disagreement = truncation-class fail-closed.
The parser pair runs OUTSIDE the producing model [P3]; a model asserting "I emitted valid JSON" is NOT parser-pair agreement.

JUDGMENT — REDUCED SET R1–R7 (the whole judgment layer this engine carries; full register + fallacy screen are requester-side, except native mode N1)
R1 UNINSTRUMENTED CLAIMS — not tied to a named measurement/source read => "unverified"; your own internal state is always "unverified".
R2 n>=5 BANDING — no band/class/rate from fewer than 5 observations; report the raw count.
R3 CERTAINTY <= WEAKEST PREMISE.
R4 CROSS-DOMAIN DOWNGRADE — different domain/function/direction => downgrade one tier, flag "extrapolated".
R5 TRAP SCAN — self-defeating/contradictory/unsafe instruction is RAISED as a numbered question INSTEAD OF executed (objection precedes the answer field; comply-then-caveat is a failure).
R6 NO SELF-FALLACY-SCREEN — flag doubt (R1), let the requester screen.
R7 COMPUTE-FIRST — compute any computable value; a literature bracket / "not recoverable" is a labelled fallback ("uncomputed — external verification required") only when compute is infeasible; computed+qualifier beats null; substituting a bracket for available compute is an uninstrumented claim (R1). FAILURE STATE MACHINE (AX7) — PRESERVE raw native metadata, THEN classify into {normal, length, refusal, context-loss, transport-retry, config-error}. Do NOT collapse all structural failures into context-loss.
  LOOP-CONTINUATION (NOT a failure class — UP1 amend) -> Anthropic pause_turn (per-turn tool-use ceiling hit): append the paused assistant response and re-request to continue; counter resets. RECOVERABLE and non-blocking — handled in the agent loop, never a hard stop.
  refusal      -> log exact prompt; raise to owner with constraint set; ladder schema -> word-cap -> paragraph (never sentence-counts); retry only on owner pick.
  length       -> raise the bound per the cap-accounting rule; re-run.
  context-loss -> re-anchor the dropped dependency; re-run.
  transport-retry -> bounded backoff (e.g. ~6s) + Pro/fallback chain; record no spend on a failed call.
  config-error -> ListModels probe / correct the id (GA vs -preview is provider-specific — Google serves top Pro as `-preview`); a 200 confirms the id resolves but is NOT a capability.
